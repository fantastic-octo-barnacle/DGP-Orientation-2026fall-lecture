# 05：Python、JavaScript、C 与 Rust 怎样运行

建议时间：65–82 分钟。

## 学习目标

- 理解 CPU 最终执行机器指令，但不同语言源码到执行之间的路径不同。
- 区分源码、解释器或运行时、编译器、链接结果、可执行文件和进程。
- 理解解释器、编译器及其版本也属于开发环境的一部分。

## 基础模型

### Python 与 JavaScript

```text
Python / JavaScript 源码（纯文本）
  → CPython / 浏览器或 Node.js 运行时
  → 运行时读取、转换并执行源码或内部表示
  → 进程产生程序行为
```

解释器或运行时本身已经是能够由系统执行的程序。脚本源码不必先变成独立本机可执行文件。

### C 与 Rust

```text
C / Rust 源码（纯文本）
  → 编译与必要的链接
  → 本机可执行文件
  → 操作系统启动进程
```

编译工具链、目标系统和链接所需的库都会影响构建结果。

## 四种语言演示

使用 [`demos/foundation/`](../../../demos/foundation/) 中实现相同行为的极小程序：

- Python：由 CPython 运行。
- JavaScript：由浏览器或 Node.js 运行，课堂选择一种即可。
- C：由 C 编译器编译并链接。
- Rust：由 Cargo 调用 Rust 工具链构建。

不解释语法，不比较语言性能，也不展开字节码、JIT、LLVM、ABI 或链接器内部实现。

## 随讲随问

- `.py` 或 `.js` 文件是否自己就是解释器？
- C/Rust 源码与编译出的文件是否相同？
- 同一份源码在不同系统上生成的可执行文件是否一定相同？
- 编译成功是否说明程序行为正确？

## 常见误解

- “所有源码都必须先变成一个独立可执行文件。”
- “解释运行意味着机器直接理解 Python 或 JavaScript 文本。”
- “安装编辑器等于安装解释器或编译器。”
- “只要语言名称相同，工具版本就不会影响结果。”

## 过渡

> 除了解释器或编译器，真实项目通常还需要系统库、第三方包及匹配版本；这些共同形成开发环境。
