# 02：文件类型、纯文本与 `.docx`

建议时间：18–32 分钟。

## 学习目标

- 理解文件系统保存的是字节，软件根据约定解释其格式。
- 理解扩展名是格式提示，不是文件内容本身。
- 区分纯文本、图片等二进制格式和复合文档格式。
- 理解源代码通常是纯文本，因此不依赖特定 IDE 才能存在。

## 讲述结构

### 文件类型

展示 `plain.txt`、`image.png`、`document.docx` 和一个没有扩展名的文件。

- 纯文本主要保存按字符编码解释的内容。
- 图片需要按图像格式解释其像素和元数据。
- 修改扩展名不会自动转换文件内容。
- 软件可能综合扩展名、文件头和内容判断格式。

### 纯文本与富文本文档

- 纯文本本身保存字符序列，不直接携带字体、段落布局和嵌入媒体。
- Markdown、HTML 或 XML 可以使用纯文本描述结构和样式，但需要其他程序解释和呈现。
- 现代 `.docx` 是 ZIP 包，内部通常包含 XML 和图片等资源。
- 旧式 `.doc` 是另一种二进制格式，不能概括为 ZIP 包。

### 最朴素的文本编辑

- Windows：使用记事本创建和查看 `.txt`，注意保存名称和扩展名。
- macOS：使用 TextEdit 的纯文本模式创建 `.txt`，避免误存为富文本。
- 不要求安装编辑器扩展。

## 随讲随做

1. 候选人创建一个新的纯文本文件并写入一句话。
2. 在文件管理器中确认文件名、扩展名和位置。
3. 用普通文本编辑器重新打开。

## 讲师演示：解构 `.docx`

1. 准备一份包含文字、样式和图片的 `.docx`。
2. 复制文件并作为 ZIP 包解压。
3. 展示内部 XML、关系文件和媒体目录。
4. 找到嵌入图片，并展示部分 XML 中的文本或排版描述。
5. 强调这是 `.docx` 格式的结构，不代表所有 Word 文件都相同。

## 常见误解

- “扩展名决定文件内部格式。”
- “二进制文件里面不存在任何可读文本。”
- “纯文本可以直接保存 Word 的全部排版和媒体。”
- “所有 Word 文档都是 ZIP 包。”

## 过渡

> 认识文件类型以后，还需要知道文件放在文件系统的什么位置，以及 shell 如何导航到它。
