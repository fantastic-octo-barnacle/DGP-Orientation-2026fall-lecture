# 03：包、版本、依赖与隔离环境

建议时间：42–60 分钟。

## 学习目标

- 理解第三方包是什么，以及使用包为什么通常需要安装。
- 理解项目对包的版本可能有兼容要求。
- 区分直接依赖和间接依赖。
- 理解包管理工具、项目清单、锁文件和隔离环境的基本职责。
- 判断哪些文件是项目定义，哪些是本机可重建产物。

## 建议幻灯片

### 1. 为什么使用第三方包

从贯穿案例的彩色输出开始：团队没有必要重新实现所有终端显示功能，可以使用他人发布的包。

需要说明：

- 包是一组可被其他项目使用的代码和相关信息。
- 在源码中写出包名，不会让包自动出现在电脑上。
- 包通常需要从包仓库取得，并安装或构建到当前项目环境。
- Python 和 Rust 使用不同工具与包仓库，但需要解决的问题相似。

本课可以提到 PyPI 和 crates.io 的名称，不讲发布流程。

### 2. 为什么需要版本

用一个简单时间线表示同一包的多个发布版本：

```text
1.0 → 1.1 → 2.0
```

核心认识：

- 新版本可能增加、删除或改变接口与行为。
- 项目能够使用某个包，不表示能够使用该包的任意版本。
- 两个包也可能对同一个依赖提出不同版本要求。
- “已经安装”不等于“安装了匹配版本”。

可以展示一个版本范围例子，但不教授完整语义化版本规则。

### 3. 依赖关系

```text
我们的程序
  → 直接依赖 A
      → 间接依赖 B
```

- 候选人主动选择的包是直接依赖。
- 直接依赖继续使用的包是间接依赖。
- 安装一个包时出现多个其他包是正常现象。

### 4. 包管理工具、清单和锁文件

| 概念 | Python 示例 | Rust 示例 | 职责 |
|---|---|---|---|
| 项目清单 | `pyproject.toml` | `Cargo.toml` | 描述项目和依赖要求 |
| 锁文件 | `uv.lock` | `Cargo.lock` | 记录解析后的具体依赖集合 |
| 环境或构建目录 | `.venv` | `target/` | 保存本机可重建内容 |

包管理工具需要完成取得、选择、安装或构建依赖等工作。本课不深入依赖解析算法。

### 5. 为什么需要隔离环境

场景：项目 A 与项目 B 需要不同依赖或不同版本。

如果所有项目随意共用同一套全局包，升级一个项目可能破坏另一个项目。隔离环境让每个项目维护自己的依赖集合。

需要避免把隔离环境描述成虚拟机；它主要隔离项目使用的解释器、包或构建状态，并不等同于完整操作系统。

### 6. 四类项目文件

| 类别 | 示例 | 通常是否提交 |
|---|---|---|
| 源码与项目配置 | `.py`、`.rs`、项目清单 | 是 |
| 锁文件 | `uv.lock`、`Cargo.lock` | 是 |
| 本机环境与构建产物 | `.venv`、`target/` | 否 |
| 输入数据与生成结果 | 示例输入、报告、日志 | 按用途决定 |

## 演示

1. Python demo 因第三方包未安装而失败。
2. 指出源码中的使用位置和项目清单中的依赖声明。
3. 展示包及其间接依赖被恢复后，程序成功运行。
4. 展示锁文件记录了比手动声明更多的具体包和版本。
5. 删除 `.venv`，证明源码和项目定义仍然存在。
6. Rust demo 构建后出现 `target/`；删除后可以重新构建。

## 课堂提问

- 在源码中写出包名后，为什么仍可能提示找不到包？
- 包已经安装，为什么项目仍可能无法运行？
- 为什么安装一个包时会出现多个其他包？
- `.venv` 或 `target/` 删除后，哪些信息使它们可以重建？

## 常见误解

- “包名出现在源码中就等于已经安装。”
- “只要包已安装，版本一定可用。”
- “锁文件与下载好的依赖内容相同。”
- “隔离环境就是虚拟机。”
- “为了让别人运行项目，应提交 `.venv` 或 `target/`。”
