# 04：环境变量、PATH、可执行文件与进程

建议时间：47–60 分钟。

## 学习目标

- 理解环境变量是传递给程序的名称和值。
- 理解 PATH 用于帮助 shell 根据命令名称寻找程序。
- 区分本机可执行文件、脚本和普通数据文件。
- 区分磁盘上的程序文件与运行中的进程。

## 讲述结构

### 环境变量

- shell 和它启动的程序可以接收一组环境变量。
- 环境变量可以表示路径、配置、开关或凭据等信息。
- 环境变量不是第三方依赖，也不是自动保存到项目中的配置文件。

只查看少量现有变量，不教授永久修改方式。

### PATH

- PATH 是一组供 shell 搜索可执行程序的位置。
- 输入完整路径时，可以明确指定要启动的程序。
- 只输入命令名称时，shell 按当前环境规则查找。
- 软件已经下载不代表其位置已经进入 PATH。
- 不同 shell、Windows 和 WSL 可以拥有不同 PATH。
- 同名命令可能命中不同位置或版本。

### 可执行文件、脚本和数据

- 原生可执行文件可由操作系统装载执行。
- 脚本通常需要对应解释器；Unix 还可能结合可执行权限和 shebang 启动。
- Windows 会结合扩展名、文件关联和相关搜索规则处理命令。
- 图片、文档等数据文件通常由其他程序打开，不是自身执行。

本课不深入 PE、Mach-O、ELF、`PATHEXT` 或权限位细节。

### 程序文件与进程

- 可执行文件保存在磁盘中。
- 每次运行通常会创建一个进程。
- 同一个可执行文件可以产生多个进程。
- 是否限制单实例是应用策略，不是操作系统的一般要求。
- 某些应用表现为单窗口，却可能在内部主动创建多个进程。

## 随讲随做

1. 查看一个普通环境变量。
2. 确认 Git 命令实际对应哪个程序位置。
3. 查看 Git 版本。
4. 对比使用命令名称与明确路径启动程序。

跨平台材料分别给出 PowerShell 与 macOS/Linux 的对应操作。

## 常见误解

- “环境变量就是项目依赖。”
- “安装完成后命令必然能被 PATH 找到。”
- “脚本文件与本机可执行文件完全相同。”
- “操作系统不允许同一程序启动多次。”

## 休息前收束

```text
操作系统提供文件系统和进程
  → 终端与 shell 提供文本操作入口
  → 路径定位文件
  → PATH 帮助命令找到程序
```

休息后进入源代码如何通过解释器、运行时或编译器产生行为。
