# 07：Git、GitHub 与项目基本结构

建议时间：94–106 分钟。

## 学习目标

- 区分 Git、GitHub、本地仓库和远程仓库。
- 理解工作区、暂存区和提交历史之间的基本关系。
- 知道 `clone`、`commit`、`push` 和 `pull` 分别改变什么。
- 能从项目结构中区分源码、说明、依赖声明、锁文件和可重建内容。

## 讲述结构

### Git 与 GitHub

- Git 是记录文件版本和变化历史的工具，可以只在本地使用。
- GitHub 是托管 Git 仓库并支持协作的平台，不等同于 Git 本身。
- 本地提交不会自动出现在 GitHub；`push` 才会把相应提交发送到远程仓库。
- `clone` 不只是下载当前文件，还会取得仓库及其已有历史和远程信息。

### 从修改到提交

```text
工作区中的文件
  → git add 选择本次要记录的变化
  → 暂存区
  → git commit 形成一个本地提交
  → git push 将已有提交发送到远程仓库
```

- `git status` 用于观察当前状态。
- `git diff` 用于检查尚未提交的具体变化。
- `git log` 用于查看已经形成的提交历史。
- 一次提交应表达一个能够说明的变化，而不是单纯“保存一下”。

只建立上述工作模型，不展开分支策略、变基、冲突处理或 Git 内部对象。

### 项目由哪些文件组成

结合 [`demos/foundation/`](../../../demos/foundation/) 展示：

- `README.md`：说明项目用途和使用方式。
- 源码：项目需要长期维护的纯文本内容。
- 项目清单与锁文件：描述项目和可复现的依赖集合。
- 测试与工具配置：记录如何验证项目。
- `.gitignore`：说明哪些本机生成内容不应被 Git 跟踪。
- `.venv/`、`target/` 等：通常可以恢复或重新生成，不直接提交。

强调 `.gitignore` 只影响未被跟踪的文件，也不会把已经提交的文件从历史中删除。

## 随讲随做

使用预先准备的候选人版课堂目录，避免现场处理账号、权限和仓库发布问题：

1. 修改一个纯文本文件。
2. 运行 `git status`，判断哪个文件发生了变化。
3. 运行 `git diff`，找到自己刚才修改的具体内容。
4. 由讲师演示 `add` 前后状态变化，再形成一次提交并查看 `log`。
5. 在 GitHub 页面上找到与本地提交对应的提交记录；说明这是执行 `push` 后的结果。

候选人若因本机 Git 身份信息未配置而不能提交，可以只完成前两步并观察讲师演示，不在课堂集中排障。

## 常见误解

- “Git 就是 GitHub。”
- “commit 等于上传或备份到云端。”
- “`git add .` 表示以后自动跟踪所有变化。”
- “写入 `.gitignore` 后，文件会从已有提交中消失。”
- “只要提交源码，其他电脑就一定能够复现项目。”

## 过渡

> Git 记录了项目发生过什么变化，但不能判断这些变化是否符合格式、类型、静态规则或预期行为；这些问题需要不同的检查工具。
