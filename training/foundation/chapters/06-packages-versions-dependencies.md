# 06：包、版本、依赖与开发环境

建议时间：82–94 分钟。

## 学习目标

- 理解第三方包需要取得并安装或构建到合适环境。
- 理解包版本可能影响接口、构建和运行行为。
- 认识直接依赖、间接依赖、构建依赖和运行依赖。
- 建立“开发环境”包含多个层次的模型。

## 讲述结构

### 环境的层次

```text
操作系统与硬件架构
  → 解释器、运行时或编译工具链及其版本
  → 系统库与链接环境
  → 第三方包及其版本
  → 项目源码、配置和环境变量
```

“环境”不是单个目录或单个工具，而是项目能够构建和运行所依赖的一组条件。虚拟环境只解决其中一部分隔离问题，不等同于虚拟机。

### 包与版本

- 包是一组可供其他项目使用的代码和相关信息。
- 在源码中引用包名，不会让包自动安装。
- 新版本可能改变接口和行为。
- “包已安装”不等于“版本匹配”。
- 项目可能声明可接受版本范围，包管理器负责选择具体版本。

本课只展示一个简单版本范围，不教授完整语义化版本规则。

### 依赖类型

- 直接依赖：项目主动选择使用的包。
- 间接依赖：直接依赖继续使用的其他包。
- 构建依赖：构建过程中需要。
- 运行依赖：程序运行时仍需要。
- 系统依赖：由操作系统或系统库提供。

### 清单、锁文件与生成内容

| 概念 | Python 示例 | Rust 示例 |
|---|---|---|
| 项目清单 | `pyproject.toml` | `Cargo.toml` |
| 锁文件 | `uv.lock` | `Cargo.lock` |
| 本机环境或构建结果 | `.venv` | `target/` |

- 清单描述项目和依赖要求。
- 锁文件记录解析后的具体依赖集合。
- `.venv` 和 `target/` 是本机可重建内容。

## 穿插演示

使用 [`demos/foundation/`](../../../demos/foundation/) 中的 Python 和 Rust 子项目：

1. 展示缺少包、工具链版本不匹配或环境不正确导致的失败。
2. 指出项目清单中的直接依赖和版本要求。
3. 展示锁文件包含更多具体依赖信息。
4. 恢复依赖后重新运行。
5. 删除 `.venv` 或 `target/` 后说明为什么可以重建。

## 常见误解

- “包名写进源码就等于包已经存在。”
- “安装一个包时出现多个包说明安装出错。”
- “锁文件就是下载好的依赖文件。”
- “虚拟环境能隔离完整操作系统。”
- “源码相同就不需要考虑工具链、系统库或目标平台。”
