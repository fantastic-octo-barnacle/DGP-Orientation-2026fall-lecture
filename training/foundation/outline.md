# 两小时基础课讲义结构

## 课程主题

整节课以“计算机开发基础”为主题。内容按照开发活动所依赖的基础层次推进：

```text
操作系统与 WSL
  → 终端、shell 与命令行
  → 文件类型、文件系统与路径
  → 环境变量、PATH、可执行文件与进程
  → 源代码、解释器、编译器与链接
  → 包、版本、依赖与开发环境
  → Git 与 GitHub
  → 测试、静态检查与 CI
  → 排障和自主学习
```

[`demos/foundation/`](../../demos/foundation/) 中的课堂 demo 只在第二小时按需穿插，不承担开场和全课叙事，也不同于Python 项目起始仓库。

## 时间安排

| 时间 | 章节 | 核心问题 |
|---:|---|---|
| 0–8 分钟 | 操作系统概述与 WSL | 操作系统为开发提供哪些基础能力？WSL 与 Windows 是什么关系？ |
| 8–18 分钟 | 终端、shell 与命令行 | 终端中是谁读取命令并启动程序？ |
| 18–32 分钟 | 文件类型与纯文本 | 代码为什么可以用文本编辑器编写？`.docx` 与纯文本有何区别？ |
| 32–47 分钟 | 文件系统、路径与导航 | shell 怎样定位文件，并通过路径操作或运行它？ |
| 47–60 分钟 | 环境变量、PATH、可执行文件与进程 | 命令如何找到程序？文件与一次运行有何区别？ |
| 60–65 分钟 | 休息 | — |
| 65–82 分钟 | 源代码怎样运行 | Python、JavaScript、C 和 Rust 的源码如何产生程序行为？ |
| 82–94 分钟 | 包、版本、依赖与开发环境 | 一个项目除源码外还依赖哪些东西？ |
| 94–106 分钟 | Git 与 GitHub | 怎样记录项目及其变化？ |
| 106–112 分钟 | 测试与开发工具 | 格式、类型、静态规则和实际行为分别由谁检查？ |
| 112–118 分钟 | 学习与排障 | 怎样分类、搜索、验证、求助和使用 AI？ |
| 118–120 分钟 | 路线自测与交接 | 下一步应该选择哪条路线，从哪里开始？ |

## 课堂活动

活动总计不超过 15–20 分钟，分散在讲解中。

课堂活动不集中成一段命令练习，而是在操作系统、shell、文件、路径、PATH、Git 和错误分类等小节中分别安排短操作。单次操作只验证刚引入的概念。

## 课程边界

课程不进行：

- 软件组工作和技术栈的重复介绍。
- Python 或 Rust 语法教学。
- uv、Rustup 或 WSL2 的完整安装流程。
- GitHub SSH key 和复杂 Git 分支操作。
- Tokio 或 asyncio API 教学。
- 正式项目需求逐条讲解。
- 正式项目代码实现。
