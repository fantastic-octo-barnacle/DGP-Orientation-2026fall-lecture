# 两小时基础课讲义结构

## 课程主题

整节课以“计算机开发基础”为主题。内容按照开发活动所依赖的基础层次推进：

```text
文件系统与路径
  → 终端、shell 与命令
  → 源代码、程序与进程
  → 包、版本、依赖与项目环境
  → Git 与 GitHub
  → 测试、静态检查与 CI
  → 排障和自主学习
```

[`demos/foundation/`](../../demos/foundation/) 中的课堂 demo 只在第二小时按需穿插，不承担开场和全课叙事，也不同于正式项目的 Demo C。

## 时间安排

| 时间 | 章节 | 核心问题 |
|---:|---|---|
| 0–10 分钟 | 开场与学习地图 | 今天建立哪些模型，哪些内容留给后续自学？ |
| 10–25 分钟 | 文件、路径、终端与进程 | 代码在哪里，命令在哪里执行，程序怎样成为运行中的进程？ |
| 25–42 分钟 | 解释、编译与运行 | Python 和 Rust 源码分别怎样变成程序行为？ |
| 42–60 分钟 | 包、版本、依赖与隔离环境 | 第三方代码怎样进入项目，为什么版本和环境会影响运行？ |
| 60–65 分钟 | 休息 | — |
| 65–82 分钟 | Git 与 GitHub | 怎样记录项目，并将可恢复的信息交给另一台电脑？ |
| 82–97 分钟 | 测试与开发工具 | 格式、类型、静态规则和实际行为分别由谁检查？ |
| 97–112 分钟 | 学习与排障 | 面对陌生问题，怎样分类、搜索、验证、求助和使用 AI？ |
| 112–118 分钟 | 网络与异步预览 | 为什么程序需要通信、并发和异步？ |
| 118–120 分钟 | 路线自测与交接 | 下一步应该选择哪条路线，从哪里开始？ |

## 课堂活动

活动总计不超过 15–20 分钟，分散在讲解中。

### 活动 1：定位文件

打开终端，判断当前目录，并尝试定位预备期创建的 `hello.txt`。

### 活动 2：观察 Git 状态

从本仓库取得课堂 demo，修改指定的纯文本文件，观察 Git 状态和差异。不要求推送。

### 活动 3：错误分类

根据若干错误现象，判断它更接近命令不存在、路径错误、依赖缺失、语法或编译错误，还是测试失败。

## 课程边界

课程不进行：

- 软件组工作和技术栈的重复介绍。
- Python 或 Rust 语法教学。
- uv、Rustup 或 WSL2 的完整安装流程。
- GitHub SSH key 和复杂 Git 分支操作。
- Tokio 或 asyncio API 教学。
- 正式项目需求逐条讲解。
- 正式项目代码实现。
