# 02：解释、编译与运行

建议时间：25–42 分钟。

## 学习目标

- 理解 Python 和 Rust 源码都是纯文本，但运行路径不同。
- 区分源代码、解释器、编译器、可执行文件和进程。
- 理解终端中的命令最终需要找到一个可执行程序。
- 初步理解 PATH 和“命令不存在”错误。

## 建议幻灯片

### 1. Python 的入门运行模型

```text
main.py
  → CPython 解释器读取并执行
  → 操作系统中出现运行进程
```

强调：`.py` 文件本身不是 Python 解释器；换一台没有合适解释器的电脑，源码不会自行运行。

### 2. Rust 的入门运行模型

```text
main.rs
  → Rust 编译器生成可执行文件
  → 操作系统启动可执行文件
  → 出现运行进程
```

强调：源码、编译生成物和运行中的进程是三个不同对象。

### 3. 模型是简化而非语言标签

- “解释型”和“编译型”用于建立第一层直觉。
- 实际语言实现可能包含更多阶段。
- 本课不讨论字节码、JIT、LLVM、链接器或 ABI。

### 4. shell 怎样找到命令

问题：输入 Git、Python 或 Cargo 的名字时，shell 怎样知道运行哪个文件？

模型：

- 命令最终对应可执行程序。
- shell 根据当前环境和 PATH 查找。
- 软件文件存在，不代表命令已经能被找到。
- 同名命令可能对应不同位置或版本。
- Windows 与 WSL 拥有不同 PATH。

只演示如何查看实际命中的程序，不教授手工修改 PATH。

## 演示

1. 展示两个项目的源文件。
2. 运行 Python demo，指出解释器参与执行。
3. 构建并运行 Rust demo，展示新产生的构建结果。
4. 启动相同程序两次，说明程序文件与进程的区别。
5. 展示一个“命令不存在”或命中不同工具版本的场景。

## 常见误解

- “安装了编辑器就等于安装了 Python 或 Rust。”
- “源代码就是可执行程序。”
- “编译成功意味着程序行为一定正确。”
- “命令名称永远对应同一个文件和版本。”

## 过渡

> 即使解释器和编译器都存在，项目仍可能因为缺少第三方包或版本不匹配而无法运行。
