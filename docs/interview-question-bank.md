# 面试题库（内部）

本文档仅供评委使用。面试公开考查范围和示例题型，但不提前公开完整题库。每个核心概念应准备若干难度相当的场景变体。

## 记录方式

每道题记录以下三级状态之一：

- **理解清楚**：能够解释原因，并说明如何验证或处理。
- **部分理解**：知道操作或部分概念，但模型不完整。
- **存在关键误解**：只能背诵命令，或对环境、协议和工具作用形成错误模型。

另行记录候选人是否诚实说明不知道、能否根据追问修正认识、是否把猜测当成事实，以及能否联系自己的项目。

## 第一批概念题

### clone 后没有 `.venv`

**问题**：从 GitHub clone 下来的 Python 项目为什么通常没有 `.venv`？怎样恢复项目？

**参考要点**：`.venv` 是本机可重建环境，不是项目源码；应根据项目元数据和锁文件恢复解释器及依赖。

**常见误解**：认为 clone 会复制作者整台电脑的环境；认为没有 `.venv` 就说明仓库不完整。

### `.gitignore` 与已跟踪文件

**问题**：已经把文件加入 `.gitignore`，为什么 Git 仍然显示它的修改？

**参考要点**：文件此前已经进入版本历史；ignore 主要影响尚未跟踪的文件，不自动取消已有跟踪。

### Windows 与 WSL 环境

**问题**：Windows 已经安装 Python，为什么进入 WSL 后可能找不到？

**参考要点**：Windows 与 WSL 是不同用户空间，具有各自的文件系统视图、PATH、软件和项目环境。

### Ruff、Pyright 与 pytest

**问题**：三个工具分别解决什么问题？

**参考要点**：Ruff 侧重格式和静态代码规则；Pyright 进行静态类型分析；pytest 运行测试验证实际行为。三者不能互相完全替代。

### 损坏日志记录

**问题**：日志文件中一行无法解析，程序应该怎样处理？

**参考要点**：记录行号和可理解原因，隔离该行，继续处理后续记录；避免吞掉所有异常或使整个文件处理失败。

### 筛选组合

**问题**：同时给出 `level` 和 `source` 时应怎样处理？

**参考要点**：按照公开规则采用“且”；所有行先验证，再对合法记录筛选，非法记录不能因筛选而消失。

### TCP 消息边界

**问题**：为什么一次 TCP 读取不一定恰好得到一条请求？

**参考要点**：TCP 提供字节流，不保留应用消息边界；一次读取可能得到半条、一条或多条消息，需要缓冲并按协议分隔符切分。

### `delay` 与并发

**问题**：为什么客户端 A 的 `delay` 不应阻塞客户端 B 的 `ping`？

**参考要点**：不同连接由独立异步任务处理，等待使用异步定时器；不应在 executor 上执行长时间阻塞等待。

### 使用参考程序定位问题

**问题**：自己的客户端无法与自己的服务端通信，怎样使用参考程序定位？

**参考要点**：分别用参考服务端测试自己的客户端，再用参考客户端测试自己的服务端，通过替换一端缩小问题范围。

## 命令行实操

使用预先准备的临时目录或小 Git 仓库，控制在 5–8 分钟。允许使用候选人熟悉的 shell 和命令自身的 `--help`，不允许联网搜索或使用 AI。

任务包括：

1. 判断当前目录。
2. 查看目录内容并找到 README。
3. 查看 README 内容。
4. 查看 Git 状态和最近历史。
5. 修改一个普通文本文件。
6. 展示修改产生的差异。
7. 根据 README 运行一条已知测试或检查命令。

准备至少两个等价版本。评委评价对操作结果的理解，不评价打字速度、特定命令写法或 shell 技巧。
