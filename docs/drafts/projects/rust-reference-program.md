# Rust 参考程序规范

参考程序由出题方使用 Rust 实现，用于为候选人的客户端或服务端提供已知可工作的通信对端。

它是独立的完整协议验证工具，不是候选人继承修改的[起始仓库](./rust-starter.md)。起始源码公开，而参考程序考核期间仅发布可执行文件。本文是待实现验证的规范草案，尚未发布程序。

## 命令行

```text
rm-recruit-reference --version
rm-recruit-reference server --bind 127.0.0.1:7878
rm-recruit-reference client --address 127.0.0.1:7878
```

所有模式提供基本 `--help` 信息。

## 参考客户端

- 连接指定服务端后进入交互模式。
- 从标准输入读取一行原始 JSON。
- 将该行作为协议请求发送。
- 输出一行原始 JSON 响应。
- 不替候选人构造协议请求。
- 标准输入 EOF 时正常关闭连接并退出。
- 等待完整响应超过可配置期限时，报告原因并关闭本次连接；默认期限允许最大合法 `delay` 及合理余量。

## 参考服务端

- 实现完整公开协议。
- 支持多个并发客户端连接。
- 一个连接的 `delay` 不阻塞其他连接。
- 单个连接的协议错误不导致整个进程退出。
- 客户端异常断开不影响其他连接。
- 等待完整请求超时后关闭该连接，释放资源，不影响其他连接。
- 收到 Ctrl-C 后停止接受新连接并及时结束空闲连接，允许在途请求在限定宽限内完成，超时后终止并回收剩余任务再退出。

超时和退出语义与[协议草案](./rust-protocol.md)一致，配置名称、默认值和精确测试阈值须在发布前统一。命令行应提供相应参数和帮助说明。

## 使用边界

- 候选人的同步客户端可连接参考服务端；参考客户端可分别连接候选人的同步和异步服务端。
- 起始项目只需验证 `ping`；完成对应任务后再验证新增动作、错误处理和并发，不能用完整协议要求起始版本全部通过。
- 并发验证需要多个连接，并比较响应先后；同步服务端不按跨连接并发要求验收。
- 故意不响应或只发送部分消息等超时测试可使用测试替身，不要求参考程序提供故障模式。

## 发布

参考程序通过对应平台的原生环境或 CI 构建矩阵构建，目标至少考虑：

- Windows x86-64。
- Linux x86-64。
- macOS Apple Silicon。
- 根据实际候选人设备情况考虑 macOS Intel。

发布文件包含版本号和 SHA-256 校验值。项目指南提示 macOS 可能阻止直接运行下载的程序，但不直接提供放行答案。

## 源码公开

- 考核期间只向候选人发布可执行文件、协议文档、版本和校验值。
- 参考实现源码不放入候选人可见仓库。
- 本轮招新结束后公开源码，供复盘和下一届维护。
- 候选人可以研究程序行为，但不要求逆向。
