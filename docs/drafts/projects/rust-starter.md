# Rust 项目起始仓库设计

本草案承接[正式路线](../../design/rust-track.md)。仓库结构和任务分工已经确认；具体模块、初始交互细节、参数默认值及验收时间阈值待实现验证。本文件不是已发布的候选人任务书，起始代码尚未实现。

## 交付结构

一个仓库下设置 `client-sync/`、`server-sync/`、`server-async/` 三个目录，各为独立 Cargo 项目，分别包含 `Cargo.toml`、`Cargo.lock`、源码和测试。

- 根目录提供 README、版本说明和通用忽略规则，不设置 Cargo.toml，不使用 workspace。
- 每个项目独立恢复依赖、构建、运行、检查和测试；也可显式指定其 manifest。
- 各自维护协议类型与校验逻辑，不额外提供共享协议 crate。
- 两种服务端分别运行；使用相同监听地址时分开启动，比较测试时使用不同端口。
- 起始源码公开。完整参考程序源码与内部评价材料不放入此仓库。

## 起始行为与候选人责任

| 项目 | 起始提供 | 候选人完善 |
|---|---|---|
| 同步客户端 | 固定单次 ping、响应显示、连接失败及关闭处理 | echo/delay、参数、连续交互、错误显示、响应超时 |
| 同步服务端 | 同步接收与读写、单连接 ping、基础错误处理 | 新动作、校验、连续请求、长度边界、断开、读取超时 |
| 异步服务端 | Tokio 入口与异步读写、顺序处理连接、ping、基础错误处理 | 完整协议、跨连接任务、读取超时、取消清理、优雅退出 |

起始两种服务端只支持 `ping`，对其他动作按未知动作处理。非法 JSON 和对端关闭等已有场景须正常处理；更完整的连续请求和边界行为由后续任务补全。起始每连接可处理的请求数及关闭时机须在发布说明中明确，不用未文档化的行为制造困难。

异步起始版本处理完当前连接后再接受下一连接，尚无跨连接并发。这是明确的能力边界，不是故障；不得预先提供完整连接任务调度、超时和退出答案。

## 起始质量

- 三个项目各自的起始测试、格式与静态检查通过。
- 提供一次请求的结构导览及已支持输入，不提供逐文件、逐函数填空步骤。
- 基础测试覆盖已有 ping、非法 JSON、未知动作、正常关闭，以及适用的连接失败场景。
- 新任务的少量正常自查用例单独组织并说明使用时机，不让默认测试因尚未完成任务而失败。
- 候选人补充异常、边界、回归与并发测试，不只运行出题方用例。
- 明确协议重复代码应保持哪些一致行为；允许复用个人实现，但需要理解同步与异步差异。

## 超时与退出验证

具体配置名称和默认值在发布前定稿，先明确行为：

| 场景 | 应验证的结果 |
|---|---|
| 客户端发送请求后迟迟得不到完整响应 | 在响应期限后报告超时，关闭本次连接；下一次操作可重新连接 |
| 连接建立后不发送完整请求 | 两种服务端在读取期限后关闭连接并释放资源 |
| 持续零星发送但始终不结束一行 | 完整请求期限仍有效，不能靠每次收到字节无限延长 |
| 正常 delay | 默认配置允许协议规定的最大合法延迟及合理处理余量 |
| A 执行 delay、B 执行 ping | 异步版本中 B 响应先于 A 延迟响应 |
| 空闲连接与在途请求同时存在时退出 | 停止接受连接，空闲连接及时结束，在途请求受退出宽限约束 |
| 在途请求超过退出宽限 | 剩余任务终止且被回收，进程有界退出 |
| 单个连接异常断开或任务失败 | 不拖垮服务端及其他连接，已结束任务得到清理 |

服务端读取期限只约束等待完整请求的阶段，不计入已开始处理的 `delay`。客户端响应期限与服务端退出宽限分别配置；不能将所有等待混成一个计时器。

测试应先确认服务已就绪、连接 A 已进入待验证阶段，再发 B 请求；记录事件顺序并设置合理上限，避免把线程调度偶然性或固定睡眠当成并发证明。可用短配置测试超时与退出，不要求每次等待默认时长。

参考程序用于协议对端验证。响应超时等故障场景可用测试替身制造，不要求参考程序提供故意失效模式。
