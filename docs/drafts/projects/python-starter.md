# Python 项目起始仓库设计

本草案定义[Python 项目](../../design/python-track.md)的起始仓库。它同时承载环境与工具链学习、代码阅读和功能扩展，候选人从同一个仓库开始并持续迭代。当前尚未实现起始代码或发布 GitHub 模板。

## 起始版本

出题方交付能直接运行的本地同步客户端与服务端：

- 文字菜单客户端与服务端完整支持 `ping`（确认服务可响应）和 `echo`（返回发送的内容）。
- 服务端另实现 `text_stats`，客户端将其接入作为基础任务。
- 完整提供连接读写、JSON 消息分帧、请求分发、基础错误响应与退出处理。
- 所有已有测试通过；不故意埋设待修复错误。

架构和第三方依赖按实际需要选择，不预先限制编程范式或固定业务依赖。结构导览应说明客户端输入、请求构造、服务端分发与处理、响应显示之间的调用关系，让刚学完基础语法的候选人能追踪一次完整请求。

## 仓库内容

- `src/`：客户端、服务端、通信与业务处理代码，具体模块在实现时确定。
- `tests/`：已有动作、通信层、基础错误处理及服务端文本统计的测试。
- `pyproject.toml`、`uv.lock`、`.python-version`：项目元数据、依赖和版本约束。
- `.gitignore`：排除 `.venv`、缓存和生成内容。
- README：用途、环境恢复、运行与检查方式、结构导览、已有功能与任务入口。
- pytest、Ruff、Pyright 配置；版本在实现与发布时验证，不在长期方案中固定。

不包含 `.venv`、个人 IDE 配置、完整新增功能答案或可直接复制的 CI workflow。新增功能的少量正常自查用例需单独说明启用时机，不能让起始版本默认测试因未实现任务而失败。

## 候选人的起始活动

1. 通过 GitHub 模板创建个人仓库，取得代码并恢复项目环境。
2. 启动两端，运行 `ping/echo` 并追踪输入、请求、处理、响应和显示。
3. 运行 pytest、Ruff 和 Pyright，理解不同检查的作用。
4. 解释项目清单、锁文件、解释器、虚拟环境和生成内容之间的关系。
5. 在可恢复的修改中观察格式、类型和测试失败报告，然后恢复通过状态。

工具学习融入同一项目，不另设环境成果提交。指南提供目标、示例、结构导览和资料方向，不逐项指定新增功能应修改的文件或函数。

## 个人成果与发布边界

候选人保留起始代码及从初始版本开始的提交历史，在 README 区分已有功能和新增功能。三个轻量检查点记录问题、验证与后续计划，不要求日报。

起始仓库维护材料预留于 [demos/projects/](../../../demos/projects/README.md)，未来发布为 GitHub 模板。候选人版发布包应包含本项目的起始代码、环境与运行说明、协议、任务要求和自查材料，形成可独立使用的项目入口。候选人版代码与文档不得混入内部面试题、评价记录或标准答案。

发布前需要实际实现、核实协议与示例、完成跨平台运行和检查。候选人仅需扩展业务与客户端功能，不承担起始框架发布工作。
