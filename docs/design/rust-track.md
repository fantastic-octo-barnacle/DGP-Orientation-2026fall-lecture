# Rust 起点路线

Rust 项目面向已经掌握任意语言基本编程概念、能够独立编写简单输入处理输出程序的候选人，不要求事先接触过 Rust。候选人在可运行的起始仓库上完善客户端、同步服务端和异步服务端，观察语言迁移、代码阅读、协议建模、错误处理、调试和异步设计能力。

项目只在本机通信，不涉及硬件、嵌入式部署、GUI、数据库、鉴权、加密或公网服务。业务保持简单，难度来自实现与验证协议、连接行为和任务生命周期。

## 起始仓库

一个 Git 仓库包含三个独立 Cargo 项目：

```text
rust-starter/
├── README.md
├── client-sync/       # 同步客户端
│   ├── Cargo.toml
│   ├── Cargo.lock
│   ├── src/
│   └── tests/
├── server-sync/       # 同步服务端
│   ├── Cargo.toml
│   ├── Cargo.lock
│   ├── src/
│   └── tests/
└── server-async/      # Tokio 异步服务端
    ├── Cargo.toml
    ├── Cargo.lock
    ├── src/
    └── tests/
```

根目录不设 Cargo 项目或 workspace，不增加共享协议 crate。三个项目各自维护协议类型与校验代码，通过同一份公开规范和测试保持一致；候选人可以复用自己编写的逻辑，但需要理解各处行为和同步、异步的差异。

### 已提供的能力

- 同步客户端完成一次固定 `ping` 请求并显示响应。
- 两种服务端均完成单连接 `ping` 交互，依次接受和处理连接。
- 异步服务端已有 Tokio 运行入口和异步读写，但未实现跨连接并发。
- 基本请求—响应、连接失败、对端关闭、非法 JSON 与未知动作的处理。
- 项目配置、运行说明、基础测试和开发检查配置，已有功能测试全部通过。

框架不故意埋 bug。支持的输入、初始连接行为与尚未实现的能力应明确写出。完整的连续交互、协议边界、超时和退出机制属于后续任务。

## 通信协议

使用本机 TCP、UTF-8 编码，每行一个完整 JSON 消息。请求包含非负整数 `id` 和 `action`；成功响应包含对应 `id`、`ok: true` 和 `data`，错误响应包含可用的请求标识、`ok: false`、错误代码和说明。

核心动作：

- `ping`：立即返回 `pong`，起始仓库已实现。
- `echo`：返回请求中的字符串，由候选人实现。
- `delay`：等待指定时间后返回字符串，由候选人实现，用于验证慢请求是否阻塞其他连接。

同一连接内顺序处理请求，不要求请求多路复用。异步阶段实现不同连接之间的并发。非法请求尽量返回错误并保留连接；超长消息等情形按公开规则关闭该连接，单连接错误不能导致整个服务端退出。

精确字段、错误代码、长度和延迟上限在[协议草案](../drafts/projects/rust-protocol.md)中细化，发布前需统一定稿。

## 学习阶段与主线层级

三个项目都属于主线成果，应分别保留为可运行、可检查的项目。层级表示学习目标，不要求候选人在每个阶段机械地完成所有工作后才接触下一阶段。

### 0. 运行与理解

- 基于起始仓库建立个人 GitHub 仓库。
- 分别运行三个 Cargo 项目及其检查，验证客户端能与两种服务端完成 `ping`。
- 追踪输入、序列化、连接读写、请求处理和响应显示。
- 理解源码、依赖、锁文件、生成内容及同步与异步等待的区别。

### 1. 扩展同步客户端

- 构造 `echo/delay` 请求，显示成功结果和错误响应。
- 支持命令行参数与连续交互，保留连接失败等已有错误处理。
- 与参考服务端验证，补充请求构造、响应处理及交互测试。

### 2. 完善同步服务端

- 建模并实现 `echo/delay`、参数校验和对应错误响应。
- 支持同一连接连续请求，非法请求后仍可处理后续合法请求。
- 处理消息长度限制、异常断开等协议边界，增加必要配置、日志和测试。
- 同时与个人客户端和参考客户端验证。

### 3. 完善异步服务端

- 在现有异步框架上实现相同的协议动作、校验和连接行为。
- 自行设计跨连接任务的创建与管理，不能仅因使用 `.await` 就认为已实现并发。
- 验证一个连接等待 `delay` 时，另一个连接先获得 `ping` 响应。
- 处理单连接任务失败或断开，不影响其他连接和服务端接收新连接。

### 4. 超时与生命周期

- 同步客户端等待响应超时后报告原因，结束本次连接。
- 服务端等待完整请求超时后结束该连接并释放资源；两种服务端都需覆盖。
- 超时参数可配置，正常范围内的 `delay` 不应被默认配置误判为故障；测试可使用短参数。
- 异步服务端收到退出信号后停止接受新连接，及时结束空闲连接。
- 允许在途请求在限定时间内完成，超过退出等待上限后终止剩余任务，回收资源并退出。
- 补充超时、并发、断开、退出等待和任务清理测试。

同步服务端不要求复制异步任务管理机制。异步完善的重点是任务追踪、取消、错误传播和有界退出。

### 扩展：CI

完成主要目标后，可使用 CI 分别执行三个项目的格式检查、编译检查、Clippy 和测试；CI 不是录取门槛。

## 参考程序

独立参考程序可作为客户端或服务端，替换通信的一端以定位问题。它实现完整公开协议，支持跨连接并发，不能与供候选人修改的起始仓库混为一体。

考核期间公开起始仓库源码；参考程序只发布可执行文件、协议、版本与校验信息，源码在考核后公开，不要求逆向。参考程序按 Windows、Linux、macOS 实际设备需求发布，详见[参考程序规范](../drafts/projects/rust-reference-program.md)。

## 工具、指南与测试

三个项目使用 Serde、Serde JSON；异步服务端使用 Tokio；较高层级使用 Clap 处理命令行参数。错误处理库不固定，可使用标准库、`anyhow` 或 `thiserror`，但需要理解选择。

分别执行 `cargo fmt`、`cargo check`、`cargo clippy`、`cargo test`，不使用 workspace 统一调用。可以推荐 rust-analyzer，不指定 IDE。

指南提供行为要求、结构导览、资料方向和验收场景，不给逐函数 TODO 或完整实现步骤。新增功能提供示例和少量正常自查用例，候选人自行补充异常、边界、回归和并发测试。并发验证必须比较事件先后，不能仅证明两个请求最终成功。

## 仓库与评价

候选人学习 [Git、GitHub 和适用 Windows 候选人的 WSL2 基础任务](./common-foundations.md)，项目不要求在 WSL2 中完成。

仓库保留三个项目的源码、测试、清单和锁文件，以及恰当的 `.gitignore`、README 和自然的提交历史。README 区分起始能力与个人新增修改，说明各项目运行和验证方法。可用简短的 `PROGRESS.md` 记录三个轻量检查点：问题、验证方法和后续计划，不要求日报。

提供框架减少初始化成本，保留协议建模、错误处理、并发与生命周期的核心能力要求，不承诺总耗时与从零实现完全相同。起始代码的已有功能不计为个人新增成果。未完成全部层级或 Tokio 完善任务，不自动淘汰；评价仍看理解、学习进展与问题分析。
