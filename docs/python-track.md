# Python 起点路线

Python 路线面向尚不能独立创建、运行和修改简单程序的候选人。路线重点是建立对纯文本代码、终端、版本控制、项目环境、依赖和基础 Python 编程的认识。

本路线不要求网络通信、异步、数据库或 GUI。

## 学习阶段

阶段按学习目标划分，阶段内部可以有多个步骤和子任务，不表示严格线性的闯关顺序。候选人可以自行跳过已经掌握的环境练习；招新方不跟踪跳过情况，而在面试中核验理解。

### Git 与 GitHub

使用纯文本文档完成基本版本控制练习。具体目标见[共同基础任务](./common-foundations.md)。

### Python 项目环境

官方项目路径采用 uv。候选人需要理解 Python、CPython、解释器、虚拟环境、依赖、项目元数据和锁文件之间的关系，而不是只记住 uv 命令。

指南可以说明普通 Python 教程中的 `python`、pip 和 `venv` 与 uv 工作流的关系。候选人自行采用 Python.org 安装包、`venv` 和 pip 也可以，但正式项目按 uv 结构检查。

#### Demo A：解释器与项目

出题方提供极小代码，显示 Python 版本、解释器路径和当前工作目录。候选人从不同位置运行程序，观察源码、解释器和工作目录之间的关系。

#### Demo B：依赖隔离

出题方提供多个使用不同依赖环境的微型项目。候选人建立并运行各自环境，观察 `.venv`、依赖声明和项目隔离，并尝试从不正确的环境运行程序。

#### Demo C：完整工具链仓库

出题方提供一个 GitHub 仓库，其中不包含 `.venv`，但包含：

- `src` 项目结构
- `tests`
- `.gitignore`
- `.python-version`
- `pyproject.toml`
- `uv.lock`
- pytest
- Ruff
- Pyright 基础类型检查

候选人 clone 仓库、恢复环境、运行程序和工具，修改代码以观察测试、格式检查、代码检查和类型检查报告的不同问题，并理解哪些文件应提交、哪些文件不应提交。

Demo C 不提供可直接复制的 CI workflow。三个环境 Demo 都不要求提交成果。

## Python 编程项目：结构化日志检查器

候选人自行建立 uv 项目和个人 GitHub 仓库。出题方提供 JSON Lines 日志，其中包含正常记录、缺少字段、字段类型错误、非法时间、未知等级、空字符串、多余字段和损坏的 JSON 行。

示意记录：

```json
{"time":"2026-09-01T12:00:00+08:00","level":"INFO","source":"client","message":"connected"}
```

固定字段为：

- `time`：带时区的 ISO 8601 时间。
- `level`：`DEBUG`、`INFO`、`WARNING` 或 `ERROR`。
- `source`：非空字符串。
- `message`：非空字符串。

### 固定依赖

运行依赖：

- Pydantic：描述和验证日志记录。
- Typer：实现命令行界面。
- Rich：显示表格、汇总和错误。

开发依赖：

- pytest：测试。
- Ruff：格式化和代码检查。
- Pyright：基础类型检查。

### 基础层

- 从文件逐行读取日志。
- 使用 Pydantic 验证记录。
- 对合法和非法记录分别计数。
- 遇到非法行时不中止整个程序。
- 输出简单统计结果。

### 标准层

- 使用 Typer 接收文件路径和筛选参数。
- 只要求按日志等级或来源筛选，避免增加不必要的业务逻辑。
- 统计各等级和来源的数量。
- 使用 Rich 输出表格与汇总。
- 合理拆分读取、验证、筛选、统计和显示逻辑。
- 为正常与异常输入编写 pytest 测试。
- 配置并运行 Ruff 和 Pyright。

### 进阶层

- 支持 JSON 报告输出。
- 流式处理较大的输入文件。
- 为错误记录生成独立报告。
- 使用 CI 自动运行测试和静态检查。

## 仓库要求

项目仓库应包含：

- 源码与测试。
- `pyproject.toml`、锁文件和必要的 Python 版本信息。
- 恰当的 `.gitignore`，不提交 `.venv`、缓存和生成输出。
- README，说明环境恢复、运行、测试和静态检查方法。
- 自然且能够反映迭代过程的 Git 历史。
- 三个轻量项目检查点；可以使用简短的 `PROGRESS.md`，不要求日报。

Ruff、Pyright 或测试尚有问题时，不自动淘汰候选人。面试重点检查其是否理解报告、是否尝试定位，以及如何计划修复。

具体日志格式、数据规模、验收案例和任务书措辞留待后续设计。
