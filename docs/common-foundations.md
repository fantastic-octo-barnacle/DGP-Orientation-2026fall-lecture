# 共同基础任务

Python 与 Rust 两条起点路线共享 Git、GitHub 和 WSL2 基础任务。它们用于建立工程基础概念，不要求候选人提交操作截图或专门展示成果；面试通过场景问题和基本命令行操作核验理解。

候选人可以自行决定是否完成已经掌握的练习。招新方不记录其跳过情况，也不要求申请豁免。

## Git 与 GitHub

练习可以只使用 Markdown 等纯文本文档，不要求先写程序。

学习目标包括：

- 理解工作目录、暂存区、本地仓库和远程仓库的区别。
- 理解 Git 与 GitHub 不是同一对象。
- 能够使用 `status`、`diff`、`add`、`commit`、`log`、`clone`、`push` 和 `pull` 完成基本工作流。
- 理解 `.gitignore` 的作用及其对已跟踪文件的限制。
- 较高层级可以接触分支、合并和一次可控的冲突。
- 理解源代码、配置文件和 Markdown 文档本质上都是可由版本控制跟踪的纯文本。

不要求掌握 rebase、cherry-pick、reflog、submodule、复杂 reset 或冷门参数。

练习仓库不作为项目成果检查。Git 的实际使用情况通过 Python 或 Rust 编程项目的个人 GitHub 仓库观察。

## WSL2

WSL2 任务适用于使用 Windows 且设备条件允许的候选人。macOS 候选人不设置对等任务。

学习目标包括：

- 区分 Windows、WSL、WSL2、Linux 内核和 Linux 发行版。
- 安装并启动一个 Linux 发行版。
- 识别 Windows 路径、Linux 路径、用户主目录和当前工作目录。
- 使用基本 shell 命令浏览、创建、复制和移动文件。
- 从 WSL 访问 Windows 文件。
- 理解 Windows 与 WSL 中安装的软件和环境彼此独立。
- 知道如何进入、退出和关闭 WSL 环境。

后续编程项目不要求在 WSL 中完成，也不要求配置 Vim 等终端编辑器。任务不涉及 systemd 服务、Docker、网络服务配置、shell 脚本或 Linux 权限管理细节。已经配置 WSL2 的候选人不必重装；存在客观设备限制时，不把未完成配置作为淘汰红线。

## CI 扩展任务

CI 不属于录取门槛。完成主要学习目标后，候选人可以使用 GitHub Actions 在干净环境中自动执行项目的测试和静态检查。

- Python：运行 pytest、Ruff 和 Pyright。
- Rust：运行格式检查、Clippy 和测试。

CI 的学习目标是理解项目复现和自动检查，不是考查 YAML 语法或复制复杂 workflow。

## 指南边界

任务指南可以提供学习目标、概念提示、官方资料方向和搜索关键词，但不提供可直接复制的完整答案、逐步命令清单或故障修复命令。候选人可以在项目期间通过搜索、AI、同学讨论和导师求助寻找具体做法。
