# 软件组计算机基础课

软件组培养流程先进行约半小时的 intro，之后留出约一周预备期，再进行 2 小时基础课。基础课不再介绍软件组具体业务，也不作为 Python 或 Rust 语言课程；它用于建立共同的计算机基础词汇、学习地图和自主学习方法，并帮助候选人开始后续约一个月的正式项目。

## 整体时间线

1. **约半小时 intro**：介绍软件组工作、技术栈、知识地图、招新流程，并布置一周预备内容。
2. **约一周预备期**：候选人完成少量共同自学和必要准备。
3. **2 小时基础课**：建立共同概念和学习方法，不讲完正式项目需要的知识。
4. **约一个月正式项目**：候选人按 Python 或 Rust 路线自行学习和实现。
5. **最终面试**：检查项目仓库，核验理解、学习过程和问题处理能力。

## 学习目标

课程结束后，候选人应当初步理解：

- 语言、工具、系统知识、工程实践和专业领域之间的关系。
- 源代码如何经过解释或编译成为正在运行的程序。
- 文件、路径、进程、环境变量、依赖和项目环境是什么。
- 客户端、服务端、IP、端口、TCP 和 HTTP 的基本关系。
- 顺序执行、阻塞、并发和异步的直观区别。
- Git、测试、类型检查、代码检查和 CI 分别解决什么问题。
- 如何阅读文档、搜索错误、构造最小实验、有效求助并验证 AI 输出。

## 建议安排

| 时间 | 内容 |
|---:|---|
| 0–15 分钟 | 计算机学习地图：语言、工具、系统知识、工程实践与专业领域 |
| 15–35 分钟 | 文件、目录、路径、终端、进程和环境变量 |
| 35–50 分钟 | 源代码、编译器、解释器、运行时、依赖和项目环境 |
| 50–70 分钟 | 客户端、服务端、IP、端口、TCP 和 HTTP |
| 70–85 分钟 | 顺序执行、阻塞、并发和异步的直观模型 |
| 85–105 分钟 | 文档、搜索、日志、最小实验、有效求助和排障方法 |
| 105–115 分钟 | 如何验证 AI 回答和生成代码 |
| 115–120 分钟 | Git、测试和 CI 在后续任务中的位置 |

## 授课方式

- 以概念讲解为主，辅以少量现场演示。
- 可以展示源码、依赖、运行和报错之间的关系。
- 可以简短演示终端、路径、Git 提交和最小问题复现。
- 不现场完整配置 Python 或 Rust 环境。
- 不讲完项目要求涉及的具体 API 和实现方法。
- 不现场实现招新项目功能。
