# Foundation Demo

本目录保存 2 小时基础课第二小时中穿插使用的演示项目。它作为当前仓库的一部分维护，不拆分为独立仓库；也不是课程开场案例、正式招新项目或 Python 项目起始仓库。

当前只保存设计说明。实际代码将在逐章讲义稳定后补充。对候选人发布材料时，必须与同仓库中的内部面试题、评价记录和标准答案保持隔离。

## 计划结构

```text
foundation/
├── README.md
├── files/
│   ├── plain.txt
│   └── sample.docx
├── python/
│   ├── main.py
│   ├── pyproject.toml
│   └── uv.lock
├── javascript/
│   └── main.js
├── c/
│   └── main.c
└── rust/
    ├── Cargo.toml
    ├── Cargo.lock
    └── src/main.rs
```

四种语言的程序实现相同的极小行为。课堂不解释语言语法，只比较源代码如何经由解释器、运行时或编译工具链产生行为。Python 与 Rust 子项目额外用于展示依赖声明、锁文件、生成环境、测试和静态检查工具。

## 课堂用途

1. 在第二小时的编程、环境、Git 和开发工具内容中按需穿插。
2. 展示 Python、JavaScript、C 和 Rust 的不同运行路径。
3. 修改指定的纯文本文件，观察 Git 状态和 diff。
4. 展示项目元数据、包版本、锁文件和生成环境。
5. 比较 pytest、Ruff、Pyright 与 Cargo 对应工具。
6. 说明 CI 如何在新环境中重复这些检查。

## 约束

- 业务代码应足够小，讲师不需要解释其算法。
- 候选人的课堂活动不依赖 Python 或 Rust 工具链已经安装。
- 指定纯文本文件的 Git 活动应能在只安装 Git 的情况下完成。
- 正式代码、测试和故障场景应按逐章讲义中的演示目标实现，并在制作幻灯片前完成跨平台实测。
